# Platform packages and client installation

## Platform matrix

| Platform | Default output | Optional one-click scripts |
|---|---|---|
| Windows | `p12`, `pass`, `ca.crt`, `使用说明.txt` | `install.ps1` / `uninstall.ps1` / `connect.ps1` + `.cmd` |
| Linux | Same as Windows | `install.sh` / `uninstall.sh` |
| macOS | Same as Windows + `<CN>.mobileconfig` | `install.command` / `uninstall.command` |
| Android | `p12`, `pass`, `ca.crt`, instructions | — |
| iOS | `<CN>.mobileconfig` (CA + identity + IKEv2) | — |

Platform names: `windows`, `linux`, `macos`, `android`, `ios`; compatible aliases include
`win`, `mac`, `darwin`, `osx`, `and`.

## Generate packages

Generate them during issuance:

~~~bash
neca cert issue alice --platforms windows,linux,macos,android,ios --zip
~~~

Rebuild from an existing certificate:

~~~bash
neca cert package alice --platforms windows,android,ios --zip
~~~

One-click installer scripts are not generated by default; enable them explicitly:

~~~bash
neca cert issue alice --platforms windows,linux --installers windows,linux
~~~

`--installers all` generates scripts for platforms with script support, but Linux/macOS
scripts should still be manually verified on the target distribution/version.

## Archives and TTL

`--zip` writes the following under `/opt/ipsec/downloads/`:

~~~text
<CN>-<YYYYmmdd-HHmmss>-<random>.zip
<same-name>.json
~~~

The default TTL is 30 minutes. Web downloads require login and are validated against
the sidecar metadata; expired downloads return 410/404. List and clean them with:

~~~bash
neca pki downloads list
neca pki downloads clean --expired
neca pki downloads clean --all
~~~

If a client receives an expired link, run `neca cert package <CN> --zip` again.

## What must not be included

- `<CN>.key`, `ca.key`, `index.txt`, `audit.log`;
- any absolute path, `..` path or server private key;
- real server identifiers (sample configurations use placeholders).

An archive contains a p12 and a password file; treat it as sensitive credentials.
Do not send it through public IM groups or unencrypted email.

## Client import notes

### Windows

1. Import `ca.crt` into "Trusted Root Certification Authorities".
2. Double-click the `p12` and import it as a "Personal" certificate; enter the
   password from `pass`.
3. Configure the IKEv2 connection as required by your organization, or run
   `connect.ps1` if it was generated.

### Linux / macOS

- On Linux, use the strongSwan `swanctl` configuration; the scripts support
  `NECA_DRY_RUN=1` for a preview.
- On macOS, import the p12 into the login keychain and install the `.mobileconfig`.
- One-click scripts are off by default; verify them on a test machine before enabling
  them.

### Android / iOS

- On Android, import the p12 through the system "Install certificate" flow; menu
  names vary by vendor.
- On iOS, install the `.mobileconfig`, then confirm the profile under
  "Settings → General → VPN & Device Management".
- If the client reports a wrong password, first check the `pass` file and keyboard
  input instead of reissuing the certificate repeatedly.

## Common questions

- **No installer script was generated**: add `--installers`. This is an intentional
  safe default.
- **Linux/macOS scripts are unverified**: target systems differ; run a dry-run first,
  then roll out in production.
- **The p12 does not open on an old Android device**: use the default `compat`
  profile; `modern` does not guarantee compatibility with old devices.
- **The archive download returns 410/404**: it expired or was cleaned; generate it
  again.
